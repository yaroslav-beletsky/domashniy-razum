# Прошивки Станций — «нужный набор» (последняя версия на платформу)

Этот файл — про **локальный кэш прошивок**: держим у себя ровно по **одной последней версии
на каждую из 23 платформ** Яндекс-устройств. Остальные версии (всего в зеркале 1769) — по
необходимости, из зеркала. Полный список — в [`all.tsv`](../firmware/all.tsv).

- **Набор:** 23 файла, суммарно **12,406,321,152 B ≈ 12.41 ГБ**.
- **Список набора:** [`firmware/needed-latest.tsv`](../firmware/needed-latest.tsv) — колонки
  `platform<TAB>version<TAB>size_bytes<TAB>url`.
- **Зеркало:** `http://144.76.194.29:62891/<platform>/<version>/update.zip` — **чужое**
  (отдаётся обычным `SimpleHTTP/0.6`, без Range-докачки).

## Как качать

Вариант А — скриптом (качает весь набор, идемпотентно, сверяет размер):

```bash
./firmware/fetch-needed.sh          # положит в ./firmware/<platform>/<version>.zip
./firmware/fetch-needed.sh /volume2/zvony   # или в другую папку
```

Скрипт для каждого файла делает `curl -L --retry 5 -C -`, после скачивания сверяет
размер с `size_bytes`, готовые файлы (нужного размера) пропускает, битые перекачивает и
печатает итог. Повторный запуск безопасен. Раскладка на диске: `<dir>/<platform>/<version>.zip`.

Вариант А2 — через туннель (если с домашней сети зеркало виснет, см. примечания ниже).
Хост `dev-desktop-ams` стоит рядом с зеркалом, оттуда всё летит на ~100 МБ/с:

```bash
ssh -f -N -D 1081 root@dev-desktop-ams        # SOCKS-прокси на localhost:1081
SOCKS=127.0.0.1:1081 ./firmware/fetch-needed.sh
```

## Куда класть

Адрес назначения задаётся первым аргументом скрипта или задаётся вручную — структуру
`<platform>/<version>.zip` из `needed-latest.tsv` сохранять как есть. Это тот же
инвентарь, что у зеркала, поэтому набор можно разложить рядом с зеркалом/на своём диске.

## Примечания

- Зеркало **чужое** — не наш хост; доступность/скорость не гарантируются.
- **Известный обрыв на 10784 Б.** Зеркало отдаётся `SimpleHTTP/0.6`; сейчас с домашней сети
  соединение стабильно встаёт после ровно **10784 байт** и дальше висит (не «медленно», а
  стоп; воспроизводится и curl, и `--http1.0`, и сырым socket'ом; HEAD при этом быстрый).
  С хоста `dev-desktop-ams` (Амстердам, рядом с зеркалом) тот же файл берётся целиком на
  100 МБ/с. Лечится туннелем (см. Вариант А2) — либо дождаться, пока стоп пройдёт.
  Скрипт ограничивает зависание (`--speed-time 30 --speed-limit 1000`), поэтому не висит вечно.
- Сервер **не поддерживает Range** (на `Range:` отвечает `200` полным телом), поэтому
  `-C -` при обрыве не «докачивает хвост»: недокачанный файл скрипт перекачивает целиком.
- Любой файл, у которого фактический размер не равен `size_bytes`, считается битым.
- Контрольные суммы (`sha256`) для нашего набора в зеркале есть не для всех версий —
  не сверял; базовая проверка здесь — точное совпадение размера.

## Санити-пометки по «последним»

Выбор «последней» — по численному сравнению версии (не по алфавиту). Ниже — что стоит знать
(выбор НЕ менял, только пометки):

**Параллельные ветки / разъезд версии и даты**
- `yandexmicro` — последняя по номеру `0.374.1.20.4835227225.20261106.302`, но у более старой ветки
  `0.373.1.16` есть сборка с датой **20261109** (`…4841751530.20261109.301`). Т.е. «самая свежая по
  номеру» и «самая свежая по дате» расходятся.
- `yandexmini`, `yandexmidi` — тоже есть соседние ветки (373/374/375) с близкими датами; брал максимальную по номеру.

**Нет встроенной даты в версии** (по строке хронологию не проверить): `chiron`, `magritte`, `monet`,
`malevich`, `nebula`, `yandexmodule_2`, `yandexstation_2`.

**Смешанные схемы нумерации**
- `yandexstation_2`: в списке есть и `500000xxxx`, и старая `1.149…20221226` — схемы несопоставимы напрямую.

**Косметика/подозрительное в строке версии**
- `jbl_link_music`, `jbl_link_portable`: строка версии с висячей точкой (`…20251219.`).

**Старый образ → риск `unknown_ca` при рутовании** (в образе может не быть современного CA-стора):
- `elari_a98` (2020-03), `lightcomm` (2020-05), `linkplay_a98` (2021-03), `prestigio_smart_mate` (2021-09),
  `yandexmodule` (2020-12). Более свежие платформы — ок.
