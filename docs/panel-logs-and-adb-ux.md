# UX-спецификация: Живой лог и Консоль ADB (`station-llm · панель`)

Целевой контур: прод-панель `http://192.168.88.207:3110` (Next.js + shadcn/ui, тёмная тема `zinc`).  
Точки применения: страница колонки `/stations/[id]` (основная), карточка колонки на `/stations` (быстрый вход) и общий экран `/logs` (единый парсер строк).  
Базовые константы вёрстки: карточки `rounded-xl border-zinc-800 bg-zinc-950/60`, моно-метаданные `font-mono text-[11px]`, тап-зоны `min-h-11` (`≥ 44×44 px`) на мобильном и `sm:h-8` на десктопе, `min-w-0` на всех flex/grid-детях.

---

## 0. Расположение на странице колонки (`/stations/[id]`)

Чтобы на телефоне не конкурировали два длинных внутренних скролла, нижняя зона страницы станции объединяется в карточку **«Диагностика»** с переключателем вкладок в шапке:

- Вкладка **`Лог`** (активна по умолчанию) — человекочитаемый живой поток событий колонки.
- Вкладка **`ADB`** (`>_ ADB · 192.168.88.79:5555`) — интерактивная консоль к этой колонке.
- На `xl` (широкий десктоп `≥ 1280 px`) допускается кнопка `⇄ Разделить` в шапке блока (лог слева `7fr`, ADB справа `5fr`). На `< xl` и мобильных — строго вкладки.
- **Быстрый вход с витрины `/stations`:** на карточке станции (`StationCard`) в правом нижнем углу рядом с IP добавляется компактная кнопка-иконка `Terminal` (`size-9`, `stopPropagation`), ведущая сразу на `/stations/[id]#adb` с открытой вкладкой ADB.

## 1. Живой лог по колонке

### 1.1. Анатомия строки-события

Сырая JSON-строка из SSE (`/api/logs/stream`) парсится на клиенте (или нормализуется в route handler) в типизированное событие. В свёрнутом виде строка состоит из **4 элементов** без JSON-скобок и технических ключей:

1. **Время** (`font-mono text-[11px] tabular-nums text-zinc-500`): `ЧЧ:ММ:СС` (локальное время браузера; при наведении — миллисекунды и дата).
2. **Иконка и пилюля категории** (`size-3.5` + короткий моно-бейдж): мгновенно считывается боковым зрением.
3. **Человеческий текст** (`text-[13px] sm:text-xs leading-snug break-words`): суть события в 1–2 строки + ключевая метрика справа моноширинным (`1.38 с`, `PID 4821`, `правило: weather`).
4. **Индикатор раскрытия / счётчик повторов**: бейдж `×N` (если схлопнуто) и шеврон `▸` (`ChevronRight`), показывающий, что по тапу доступен сырой payload.

```text
Desktop (1 строка на событие, выравнивание по базовой сетке):
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 14:02:11  🎙 [Речь]     «Алиса, почему небо синее»                         ▸     │
│ 14:02:11  ⇄  [Маршрут]  Ответит модель · default_route → llm               ▸     │
│ 14:02:13  ✦  [Ответ]    «Солнечный свет рассеивается в атмосфере…»  1.42 с ▸     │
│ 14:02:14  🔊 [TTS]      Озвучено · 148 симв.                        920 мс ▸     │
└──────────────────────────────────────────────────────────────────────────────────┘
```

| **Маршрут → Модель (`route-llm`)** | `GitBranch` | `text-emerald-400` · `bg-emerald-950/60 border-emerald-800/70` | `text-zinc-300`, метка `→ LLM` `text-emerald-300` | `native_route_decision` / `route=llm` |

### 1.4. Группировка и схлопывание

1. **Подряд идущие дубли (`×N`):**
   - Если у новой строки совпадают `(kind, humanTitle, level)` с предыдущей (например, периодические `health`, `adb reconnect`, одинаковый `warn`), новая строка не плодит дубль: у последней строки обновляется время до актуального, а справа растёт пилюля `×2` → `×15` (`bg-zinc-800 text-zinc-300 font-mono text-[10px] px-1.5 rounded-full`).
   - При раскрытии схлопнутой строки показывается диапазон: `Первое: 14:01:10 · Последнее: 14:03:30 (15 событий)` и JSON последнего события.
2. **Склейка многострочных стектрейсов (`Traceback` / `panic`):**
   - Строки без собственного таймстампа, начинающиеся с `Traceback`, пробелов `  File "..."` или `at ...` в течение `250 мс` после строки ошибки, приклеиваются к этому событию в поле `rawStack`, а не рендерятся десятком оторванных строк. В заголовке ошибки выводится последняя осмысленная строка исключения (`RuntimeError: phone TTS failed: FAIL`) и бейдж `стек`.
3. **Визуальная связка голосового раунда (Turn Grouping):**
   - События внутри одного обращения (`Речь` → `Маршрут` → `Ответ` → `TTS` с разрывом `< 8 с`) соединяются слева тонкой вертикальной линией `border-l border-zinc-800` (без лишних вложенных карточек), чтобы один вопрос читался единым блоком. Между разными диалогами — отступ `mt-1.5`.

### 1.5. Раскрытие сырого события по тапу (Pretty-JSON)

- Вся строка кликабельна (`role="button"`, `min-h-11` на тач-экранах).
- Тап раскрывает под строкой блок `rounded-lg border border-zinc-800/90 bg-zinc-950 p-2.5 my-1`:
  - **Шапка раскрытия:** `источник: quasar-bridge · seq #142 · 2026-11-07 17:05:42.090` + кнопки `[Копировать JSON]` и `[Сырая строка]` (с фидбеком `Скопировано ✓` на 1.5 с).
  - **Тело:** отформатированный `JSON.stringify(obj, null, 2)` (`font-mono text-[11px] leading-relaxed overflow-x-auto`), ключи `text-zinc-400`, строки `text-emerald-300`, числа/булевы `text-amber-300`. Все секреты уже замаскированы сервером (`sk-…[masked]`, `Bearer …[masked]`).
  - Если исходная строка не JSON (вывод `control.sh` или стектрейс) — блок рендерит `pre` с сохранением переносов.
- **Защита от «убегания»:** раскрытие любой строки автоматически ставит автоскролл на мягкую фиксацию (`stick = false`), чтобы живой поток не унёс открытый JSON из-под глаз.

### 1.6. Панель инструментов: фильтры, поиск, пауза, автоскролл, копирование, очистка

```text
Desktop-шапка лога:
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [Лог · ● live] [ADB · 192.168.88.79]           Источн: [Мост + Панель ▾] [+шум] │
├──────────────────────────────────────────────────────────────────────────────────┤
│ [Все] [Диалог] [Мост/ADB] [Ошибки ●1]   [🔍 Поиск по тексту и JSON…] [⏸] [📋] [✕]│
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **Фильтр по типу (чипы в 1 клик):**
  - `Все` (кроме скрытого `debug`)
  - `Диалог` (`stt`, `route-*`, `llm`, `tts` — идеально для неспециалиста: видно только «что спросили и кто ответил»)
  - `Мост / ADB` (`system`)
  - `Ошибки` (`warn` + `error`, с живым счётчиком красной точкой `● 2`, если в буфере есть ошибки)
- **Фильтр источника (компактный селект):** `Мост + Панель` (по умолчанию на странице станции), `Только мост (quasar-bridge)`, `Голос (belch-voice)`, `Прямой adb tail`.
- **Тоггл `+ шум (debug)`:** чекбокс/кнопка `Bug`, включает показ `debug`-строк и неразобранных healthcheck-запросов.
- **Поиск (`Search`):**
  - Ищет без учёта регистра одновременно по человеческому тексту **и** по сырой строке JSON (можно ввести `yandex_home`, `4821` или `погода`).
  - Подсвечивает совпадение (`bg-amber-500/25 text-amber-200 rounded px-0.5`). Кнопка `×` внутри поля сбрасывает запрос.
- **Пауза и автоскролл:**
  - Кнопка `⏸ Пауза` замораживает ленту; входящие SSE-события складываются в фоновый кольцевой буфер (до 500 строк), на кнопке тикает счётчик `▶ Продолжить (+14)`.
  - При ручном скролле вверх на `> 32 px` автоскролл отключается сам, в правом нижнем углу появляется плавающая кнопка `↓ В конец` (если пришли новые строки — `↓ В конец · +6`).
- **Копирование (`Copy`) и Очистка (`Trash2` / `Eraser`):**
  - Выпадающее меню у `📋`: `Копировать видимые (текст)` и `Копировать видимые (сырой лог / JSONL)` — копирует текущий отфильтрованный срез (с уже замаскированными секретами).
  - `Очистить` ставит клиентскую отсечку `clearedAt = Date.now()` и показывает ненавязчивую ссылку в пустом окне `Лог очищен · [Вернуть хвост (84 строки)]` на случай случайного нажатия.

### 1.7. Состояния лога

1. **`online` (штатная работа):** зелёная пульсирующая точка `bg-emerald-400 station-pulse` + подпись `live`.
2. **`пусто` (станция `online`, строк ещё нет или сработал фильтр):**
   - Без фильтра: иконка `Waves` (`text-zinc-700`), текст: *«На связи, ждём событий. Скажите что-нибудь колонке — реплика и маршрут сразу появятся здесь.»*
   - С активным фильтром/поиском: *«По запросу „…“ совпадений нет (скрыто 62 строки)»* + кнопка `[Сбросить фильтр]`.
3. **`offline` (станция недоступна или обрыв SSE):**
   - Ранее накопленные строки **не стираются** (остаются с `opacity-75`, чтобы можно было посмотреть, что произошло перед падением!).
   - В шапке: серо-янтарная точка `bg-amber-400/80` + `в ожидании (автореконнект…)`.
   - Внизу ленты прикреплена спокойная плашка: `WifiOff` *«Связь с колонкой потеряна в 17:12:05 — поток подхватится сам, когда станция вернётся в сеть.»*

### 1.8. Мобильный вид лога (`360–430 px`)

- **Никаких разъезжаний:** контейнер лога `overflow-x-hidden`; у текста реплик `break-words` (не `break-all`, чтобы русские слова не рвались по одной букве!), а длинные идентификаторы моделей/правил обрезаются `truncate max-w-[11rem]`.
- **Компактная двухстрочная карточка события на `< sm`:**
  - Строка 1 (мета): `17:05:42` · иконка + пилюля `[Ответ]` · справа тайминг `1.88 с` и `▸`.
  - Строка 2 (суть, во всю ширину): `«Сердечник сжимается и разжимается…»`
- **Панель управления в 2 аккуратных ряда без переносов в кашу:**
  - Ряд 1: вкладки `[Лог ●]` `[ADB]` + справа иконки `[🔍]` `[⏸]` `[⋯]` (все кнопки `size-11` — `44×44 px`; внутри `⋯` лежат `Источник`, `+ шум (debug)`, `Копировать срез`, `Очистить`). Тап по `🔍` плавно раскрывает строку поиска под шапкой.
  - Ряд 2: горизонтальная лента чипов `overflow-x-auto no-scrollbar` (`[Все] [Диалог] [Мост/ADB] [Ошибки ●1]`).

## 2. Консоль ADB по колонке

Инженерная консоль выполняет одиночные неинтерактивные команды вида `adb -s <device> shell <cmd>` через серверный контейнер панели к уже зарегистрированной колонке. Секреты в `stdout`/`stderr` на сервере обязательно проходят через `maskSecrets` (например, при чтении env-файлов ключи `sk-…`, `Bearer …` и `*_KEY=` заменяются на `…[masked]`).

### 2.1. Шапка подключения и статус

Верхняя полоса консоли всегда однозначно показывает, **к какому адресу** сейчас идут команды и живо ли соединение:

- **Статус `online`:** зелёная точка `bg-emerald-400` + моно-бейдж `192.168.88.79:5555` + пинг проверки `12 мс` + контекст пользователя (`uid=0(root)` или `shell`, кешируется после первой проверки).
- **Статус `offline`:** красная/серая точка `bg-red-400` + `192.168.88.79:5555 · нет ответа` + причина в 1 фразу.
- **Статус `applying` (занята панелью):** янтарная точка `bg-amber-400 animate-pulse` + `идёт применение настроек…` (отправка изменяющих команд временно приглушена, чтобы не сорвать `control.sh restart`).
- **Кнопки справа в шапке:**
  - `↻ Переподключить` (`RefreshCw`, принудительный `adb connect <device>` + `echo ok` без 20-секундного кэша).
  - `Очистить вывод` (`Eraser`).

### 2.2. Быстрые кнопки (пресеты)

Над областью вывода (или над полем ввода на мобильном) расположен ряд быстрых чипов (`font-mono text-[11px]`, высота `h-10 sm:h-7`).  
Безопасные диагностические чипы выполняются **в 1 тап** сразу при нажатии (и дублируют команду в ленту вывода, чтобы инженер видел, что именно запустилось):

| Подпись на кнопке | Фактическая shell-команда | UX-примечание |
|---|---|---|
| `id` | `id` | Мгновенная проверка `uid/gid` и отзывчивости shell |
| `getprop` | `getprop` | Вывод ~300+ строк автоматически сворачивается до первых 25 строк с кнопкой `[Показать все N строк]` и фильтром внутри блока |
| `df` | `df -h 2>/dev/null \|\| df` | Таблица разделов (`/data`, `/system`, `/tmp`) с горизонтальным скроллом без переноса строк |
| `top` | `top -b -n 1 \| head -n 35` *(с фоллбэком `top -n 1 \| head -n 35` для busybox/toybox)* | **Важно:** голый `top` без `-n 1` в неинтерактивном `adb shell` зависает до таймаута; пресет делает чистый разовый снимок процессов |
| `ls /data/opt/quasar-bridge` | `ls -la /data/opt/quasar-bridge` | Проверка файлов моста (`config.json`, `runtime.env`, `service.log`, `app/`) |
| `⚠ reboot` | `reboot` | Отделён разделителем `border-zinc-800`, стиль `border-red-900/60 text-red-400 hover:bg-red-950/40`; **никогда** не выполняется в 1 клик — открывает подтверждение (п. 2.5) |

### 2.3. Поток вывода (Output Stream)

Вывод строится не «слепой простынёй», а **карточками выполненных команд** хронологически сверху вниз (автоскролл к новому запуску):

```text
Desktop-макет консоли ADB:
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [Лог · ● live] [>_ ADB · ● 192.168.88.79:5555 · 11 мс]   [↻ Переподкл.] [Очист.] │
├──────────────────────────────────────────────────────────────────────────────────┤
│ Быстрые: [id] [getprop] [df] [top] [ls /data/opt/quasar-bridge]  │  [⏻ reboot]  │
├──────────────────────────────────────────────────────────────────────────────────┤
│  17:14:02  $ id                                              exit 0 · 38 мс [📋] │
│  uid=0(root) gid=0(root) groups=0(root)                                          │
│ ──────────────────────────────────────────────────────────────────────────────── │
│  17:14:09  $ ls -la /data/opt/quasar-bridge                  exit 0 · 54 мс [📋] │
│  drwxr-xr-x  4 root root   4096 Nov  7 14:10 .                                   │
│  drwxr-xr-x  5 root root   4096 Oct 12 09:00 ..                                  │
│  drwxr-xr-x  2 root root   4096 Nov  6 22:15 app                                 │
│  -rw-------  1 root root   1842 Nov  7 14:10 config.json                         │
│  -rw-------  1 root root    312 Nov  7 14:10 runtime.env                         │
│  -rw-r--r--  1 root root 184920 Nov  7 17:14 service.log                         │
├──────────────────────────────────────────────────────────────────────────────────┤
│  $ [ введите shell-команду…                              ] [🕘 История] [▶ Пуск] │
└──────────────────────────────────────────────────────────────────────────────────┘
```

Детали блока вывода:
- **Шапка каждого запуска:** время `17:14:09`, строка `$ <cmd>` (`text-emerald-400` при `exit 0`, `text-red-400` при `exit != 0`), справа код возврата `exit 0`, длительность `54 мс`, кнопки `[↻ Повторить]` и `[📋 Копировать]`.
- **Разделение потоков:** `stdout` рендерится `text-zinc-200`, `stderr` — отдельным подблоком `text-amber-300 bg-amber-950/20 border-l-2 border-amber-500/60 pl-2` (чтобы предупреждения утилит не смешивались с чистым выводом).
- **Форматирование таблиц:** `font-mono text-[11px] leading-5 whitespace-pre overflow-x-auto` — вывод `df`, `ps`, `top`, `ls -la` сохраняет ровные колонки и прокручивается по горизонтали внутри блока, не растягивая саму страницу.
- **Сворачивание больших ответов:** если в `stdout` больше `40 строк` (например, `getprop`), показываются первые `25 строк` и кнопка `Развернуть ещё 312 строк (24 КБ)`.

### 2.4. Поле ввода команды и история

- **Атрибуты поля ввода (критично для смартфонов):**
  `type="text"`, `inputMode="url"` или `"text"`, `autoCapitalize="none"`, `autoComplete="off"`, `autoCorrect="off"`, `spellCheck={false}`, моноширинный шрифт `font-mono text-sm sm:text-xs`. Телефон не пытается сделать первую букву заглавной (`Id` вместо `id`) и не заменяет `--` на длинное тире `—`.
- **Перехват интерактивных ловушек на вводе:**
  Если пользователь вручную ввёл голое `top`, `ping 8.8.8.8` (без `-c`), `tail -f ...` или `sh`/`su` без аргументов — под полем до или во время запуска всплывает тихая подсказка: *«Консоль выполняет разовые команды (таймаут 15 с). Подсказка: `[Подставить top -n 1]` / `[ping -c 4 …]`»*.
- **Кнопка запуска / отмены:**
  - В покое: `▶ Пуск` (`Enter` с клавиатуры).
  - Пока команда бежит: кнопка меняется на янтарную `■ Стоп (3 с)` — клик обрывает запрос и посылает `SIGKILL` дочернему процессу `adb` на сервере.
- **История последних команд:**
  - Хранится в `localStorage` (`station-llm:adb-history`, до 30 последних уникальных команд, без дублей подряд).
  - **На десктопе:** клавиши `ArrowUp` / `ArrowDown` в фокусе инпута листают историю (с сохранением текущего черновика на нулевой позиции) + кнопка `🕘`.
  - **На мобильном и десктопе по кнопке `🕘` (`History`):** открывается `Popover` (десктоп) / нижний `Drawer` (мобильный) со списком последних команд:
    - Тап по строке — подставляет команду в поле ввода для редактирования.
    - Кнопка `▶` справа от строки — сразу выполняет команду (если она не из опасного списка).
    - Внизу списка — кнопка `Очистить историю`.

### 2.5. Предупреждения по опасным командам

Любая команда перед отправкой проверяется на клиенте (для UX-диалога) и повторно помечается на сервере (флаг `confirm: true` в API) по регулярным выражениям опасных действий:

1. **Перезагрузка и питание:** `\b(reboot|poweroff|halt|shutdown)\b`
2. **Удаление и перезапись системных/мостовых путей:** `\brm\s+(-[rRf]+\s+|.*quasar-bridge)`, редирект `>\s*/data/opt/quasar-bridge/(config\.json|runtime\.env)`, `\bdd\b`, `\bmkfs\b`
3. **Остановка моста или демона связи:** `\b(kill|killall|pkill)\b`, `control\.sh\s+stop`, `stop\s+adbd`, `ifconfig\s+wlan0\s+down`

**Сценарий подтверждения (на примере `reboot`):**
- При клике на чип `⏻ reboot` или вводе `reboot` + `Enter` команда **не уходит** сразу. Открывается компактный диалог подтверждения (`Dialog` на десктопе / `Drawer` снизу на телефоне):
  - Заголовок с иконкой `AlertTriangle` (`text-red-400`): **«Перезагрузить колонку „Гостиная“?»**
  - Пояснение: *«Команда `reboot` немедленно прервёт воспроизведение и перезапустит устройство. Колонка пропадёт из сети примерно на 45–60 секунд.»*
  - Кнопки (`min-h-11` на мобильном): `[Отмена]` (фокус по умолчанию!) и красная `[Перезагрузить колонку]`.
- **Поведение после подтверждения `reboot`:**
  Поскольку при `reboot` соединение ADB штатно рвётся без красивого `exit 0`, консоль **не пугает** пользователя красной ошибкой `device closed`:
  - В ленту пишется янтарный статус-блок: `⏻ Команда перезагрузки отправлена · ждём возвращения колонки в сеть… (22 с)` с автоопросом `adbWarmup` раз в 3 с.
  - Как только станция ответила — блок зеленеет: `✓ Колонка снова на связи (через 48 с) · мост healthy`.

### 2.6. Понятная обработка ошибок ADB

Сырой `stderr` утилиты `adb` никогда не сваливается на пользователя без расшифровки. Консоль показывает двухуровневое сообщение: **человеческий диагноз + действие** и ниже приглушённый тех-оригинал:

| Сырая ошибка `adb` / системы | Что пишет панель человеку | Кнопка быстрого действия |
|---|---|---|
| `failed to connect to '…:5555': Operation timed out` / `No route to host` / `device offline` | **Колонка не отвечает по сети (`192.168.88.79:5555`).** Проверьте питание станции и Wi-Fi или переподключите сессию. | `[↻ Переподключить]` |
| `device unauthorized. This adb server's $ADB_VENDOR_KEYS is not set` | **Колонка отклонила ключ панели (`unauthorized`).** Авторизационный ключ в томе `secrets/adb` не совпадает с ключом на станции. | — |
| `sh: <cmd>: not found` (`exit 127`) | **Команда `<cmd>` не найдена на станции (`exit 127`).** На колонке урезанное окружение Linux (busybox/toybox) — проверьте имя утилиты. | `[Подставить busybox --list]` |
| Таймаут выполнения (`> 15 000 мс`, убито сервером) | **Прервано по таймауту (15 с).** Скорее всего, команда ждёт интерактивного ввода или работает бесконечно. Используйте флаги ограничения (`-n 1`, `-c 3`). | `[Править команду]` |
| `more than one device/emulator` / `device '…' not found` | **Сессия ADB потеряла привязку к устройству.** Сервер панели сейчас переподключит `adb connect`. | `[↻ Переподключить и повторить]` |
| Станция в статусе `applying` (идёт смена режима/модели) | **Подождите ~10 с: панель сейчас перезапускает мост на колонке.** Выполнение произвольных команд во время записи конфига заблокировано. | — |

### 2.7. Мобильный вид консоли ADB (`360–430 px`)

```text
Мобильный экран (375 px, вкладка ADB):
┌──────────────────────────────────────┐
│ [Лог ●] [>_ ADB ● .88.79]   [↻] [🧹] │
├──────────────────────────────────────┤
│ (id) (df) (top) (ls …/bridge) (getp…)│ ← свайп чипов по горизонтали
├──────────────────────────────────────┤
│ 17:14:02 · $ id        exit 0 · 38мс │
│ uid=0(root) gid=0(root)              │
│ ──────────────────────────────────── │
│ 17:15:10 · $ df -h     exit 0 · 49мс │
│ Filesystem      Size  Used Avail Use%│ ← свайп таблицы внутри блока
│ /dev/data       3.6G  1.1G  2.5G  31%│
├──────────────────────────────────────┤
│ $ [ls -la /data/opt…  ] [🕘] [▶]     │ ← инпут h-11, кнопки 44×44 px
├──────────────────────────────────────┤
│ Опасные действия:       [⏻ reboot…]  │ ← убрано из-под пальца при свайпе чипов!
└──────────────────────────────────────┘
```

Ключевые мобильные решения для ADB:
1. **Защита от случайного тапа по `reboot`:** на мобильном свайп-ряду быстрых чипов `reboot` **не ставится** вплотную к `ls` и `top` (чтобы палец при прокрутке ленты чипов не задел перезагрузку) — кнопка `[⏻ Перезагрузить колонку…]` вынесена либо в конец с явным отступом + двухшаговым `Drawer`-подтверждением, либо в тихую плашку под инпутом / меню `⋯`.
2. **Устойчивость к экранной клавиатуре (`svh` / `dvh`):** высота окна вывода задаётся гибко (`min-h-52 max-h-[48svh]`), а при фокусе в поле ввода страница прокручивает блок консоли так, чтобы и строка ввода `$`, и последние 6–8 строк вывода оставались над клавиатурой.
3. **Крупные контролы без наслоений:** поле ввода `h-11 text-base` (`16px` на `< sm`, чтобы iOS Safari **не делал принудительный авто-зум** страницы при тапе в инпут!), кнопки `🕘 История` и `▶ Пуск` — квадраты `size-11` (`44×44 px`).

## 3. Сводка контрактов для реализации (`coder`)

1. **Клиентский парсер логов (`lib/logParser.ts`):** чистая функция `parseLogLine(raw: string, fallbackTs: number) → ParsedLogEvent` (распознаёт JSON `quasar-bridge` и `belch-voice`, строки `control.sh`, локальные шаги `[панель] …`, HTTP access-строки и `Traceback`; никогда не бросает исключений).
2. **Агрегатор потока:** схлопывание соседних одинаковых `(kind, title, level)` с инкрементом `repeatCount` и склейка строк стектрейса в `rawStack` предыдущей ошибки.
3. **Серверный роут ADB (`POST /api/stations/[id]/adb`):**
   - Принимает `{ command: string, confirm?: boolean, timeoutMs?: number }` (макс. `timeoutMs` — `30000`, по умолчанию `15000`).
   - Отказывает с `409 Conflict`, если по станции активен `apply`, и с `428 Precondition Required` (`requiresConfirm: true`), если команда матчится на список опасных без `confirm: true`.
   - Выполняет `adbExec(["-s", device, "shell", command], timeoutMs)`, прогоняет `stdout` и `stderr` через `maskSecrets()`, возвращает `{ ok, exitCode, stdout, stderr, ms, device, hint? }`.
