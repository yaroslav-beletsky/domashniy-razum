# Охота за приватным ключом листа `quasar.yandex.net` в прошивке

**Короткий итог:** в прошивке колонки приватного ключа, чей RSA-модуль совпадал бы с
публичным ключом серверного листа `quasar.yandex.net`, **нет**. Более того — в rootfs нет
ни одного RSA-2048 приватного ключа вообще. Единственный вшитый приватный ключ во всей
прошивке — `teetz` (RSA-1024, Android attestation).

Проверено на образе `yandexmini_2`, `0.369.1.46.4778262943.20261013.299`
(`/private/tmp/fw`, распаковка `rootfs.ubifs` → `out`, `out2` — идентичны).

## Что именно искали

- Целевой лист: `real1.pem` (CN=quasar.yandex.net, GlobalSign).
- Контрольная метка: `md5("Modulus=" + hex(n).upper() + "\n")` == `138b4f1e7311da18ec40b3e6d5e872e3`
  (подтверждено `openssl x509 -modulus | openssl md5`).
- Первые байты модуля (BE): `AA988212F3D8F414B7D22E8C385194…`
- Живой лист СЕЙЧАС другой (eMudhra, `B5E7123B…`) — учтён отдельно.

## Что перепробовали (и результат)

Всё — по всему дереву `/tmp/fw` (rootfs + зашифрованные `boot/dt/u-boot/rootfs.ubifs`):

1. Метки `-----BEGIN/END …-----` — это строковый пул библиотек, не PEM-контейнер.
2. Поиск подстрок `MII` — 0 у `maind`.
3. Поиск сырых байт модуля (BE): `AA988212F3D8F414…` (real1) и `B5E7123B…` (live) — 0.
4. Поиск модуля во всех простых кодировках — реверс целиком, пословный LE (2/4/8 байт) — 0.
5. Поиск hex-строки модуля (нижний/верхний регистр) — 0.
6. `load_der_private_key` по всем блобам `30 82` во всём rootfs — единственный ключ: `teetz`.
7. Паттерны `02 01 00 02 82 01 01` (RSA-2048), `02 82 01`/`02 81` и т.п. — только teetz (RSA-1024).
8. Base64-руны (>=100/>=56 симв.) + попытка распарсить как ключ/серт — только пул строк.
9. Поиск DER-сертификата real1 и его SPKI — 0.
10. Скан всего домашнего каталога `~` на байты модуля — 0.
11. Зашифрованные `boot.img.encrypt` (ядро зашифровано, ни gzip, ни `Linux version`),
    `dt.img.encrypt`, `u-boot.*.encrypt` — модуль в них не встречается.

## Что реально есть ключевого/сертификатного в прошивке

| Файл | Что это |
|---|---|
| `lib/teetz/…ta` @689680 | **Eдинственный** приватный ключ (RSA-1024, Android Software Attestation) |
| `system/vendor/quasar/ota_script.pub` | публичный RSA-2048 (проверка подписи OTA), приватного нет |
| `system/vendor/quasar/certs/ca-certificates.crt` | CA-бандл (122 серта) |
| `maind` @5801176 | реальный PEM — только `DH PARAMETERS`; прочие метки — пул строк |
| `usr/bin/keymaster_svc` | только `-----BEGIN PUBLIC KEY-----` |
| `matter/paa/*.der` + в `maind` | Matter PAA/SelfSigned (EC), серверного RSA-ключа нет |

Ключи в `maind`/`keymaster_*` генерятся в рантайме («Generating rsa key…»), не вшиты.

## Вывод

Колонка — TLS-клиент: она проверяет лист сервера по trust store, а приватный ключ листа
лежит на серверах Яндекса. Отдельного «ключа колонки под серверный лист» в OTA-образе нет.

Рабочий восстановимый ключ в этой истории — промежуточный **eMudhra `EM OV TLS CA - G3C`**
(ECDSA P-384, приватный скаляр = **4**; у hu553in в README «1», но `issuer.key` даёт 4 — сверено,
`int.pem` == их `issuer.pem`) — им и подписывают свой лист (eQuasar/miilv). Trust store
колонки специально расширен под это; в самом бандле есть пометка Яндекса:

```
# - emSign ECC Root CA - G3: cross-signs eMudhra intermediates with compromised keys, https://st.yandex-team.ru/SK-12466
```

## Проверка пригодности листа к стенду

- `openssl verify -CAfile <бандл колонки> -untrusted real2.pem real1.pem` → **OK** (GlobalSign).
  То есть стоковый бандл готов принять лист real1, будь его приватный ключ под рукой.
- Живой eMudhra-лист против стокового бандла «в лоб» не сходится (в бандле нет AAA),
  но у eMudhra есть кросс-вариант под emSign (см. выше).

## Где ещё искать (если очень надо)

- `/data` (не входит в OTA): рантайм-ключи keymaster, glagol; но серверного ключа и там не ждём.
- Зашифрованные `boot/dt/u-boot` (нужен ключ загрузчика для расшифровки) — там ядро, не TLS.
- Другой образ — `yandexmidi` (.50) или иные модели (Station 1 Android).

## Артефакты

Собрано в `/tmp/fw/`:
- `global_leaf.pem` (= real1, лист quasar.yandex.net, GlobalSign) — OK против бандла колонки;
- `global_int.pem` (= real2, GCC R46 DV TLS CA 2025);
- `global_root.pem` (= real3, GlobalSign Root R46);
- `global.key` — **отсутствует** (ключа в прошивке нет).
